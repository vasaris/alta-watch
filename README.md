# alta-watch

Бот, который каждые 2 минуты проверяет источники об ALTA banka a.d. Beograd и публикует
новое по-русски в Telegram-канал. Если нового нет, молчит. Работает на GitHub Actions.

## Источники и правила допуска

| Источник | Что это | В канал |
|---|---|---|
| aod.rs — новости, объявления (PDF/DOCX), страница «Поступци у току» | официальный | отдельным постом: перевод коротких, тезисы длинных |
| nbs.rs — RSS + запасной парсинг пресс-центра | официальный | отдельным постом |
| altabanka.rs — заявления и новости банка | сам банк | отдельным постом с пометкой «позиция банка» |
| N1, Danas, Nova ekonomija, Forbes Srbija, Nova.rs, Radar, Insajder, RTS, RTV, 021.rs, Beta, BIZLife | пресса (RSS/Atom) | важное и новое — пост (не больше 3 за прогон); среднее — подборка; перепечатки — нет |
| Telegram-каналы (@novisadaily, @Serbia, @volna_srbjia, @novostiserbii) | неофициальное | **только сигнал владельцу**, не в канал (`TG_PUBLIC=1` включает подборки) |

Модель (Anthropic, Haiku) для каждого материала определяет **предмет** (ALTA Beograd / ALTA Pay /
группа / ALTA Bitola / другой банк / система), важность 0–10, **новизну** 0–10 относительно
реестра фактов, уже опубликованного и ожидающего публикации, пишет русский заголовок и тезисы,
помечает **непроверенные** утверждения (слухи, анонимные источники, обвинения политиков) и
из официальных документов извлекает **факты процедуры** (банк-выплатчик, даты, документы, сроки).

- Документы про другой банк не публикуются, даже официальные.
- Непроверенное не публикуется — уходит сигналом в админ-чат.
- Без ответа модели ничего не публикуется: материал ждёт следующего прогона (до 5 попыток, потом карантин).
  Если не отвечает сам API (нет кредитов, auth, 429, 5xx) — попытки **не считаются**, модель в этом
  прогоне больше не вызывается, владелец получает алерт, а после восстановления — уведомление.
- Без ключа модели бот останавливается (кроме `DRY_RUN`).
- Перепечатка с тем же заголовком (одинаковые слова, числа и отрицания) отсеивается до вызова модели.
- Отложенная пресса хранится с метаданными (`retry_items`): повтор не зависит от того, осталась ли статья
  в короткой RSS-ленте. Свежесть считается на момент первого обнаружения, а не повтора.
- Если источник отдал больше 20 «новых» разом, они идут в карантин и пересматриваются по 10 за прогон, а не хоронятся.
- Объявления AOD старше 30.10.2026 — никогда. Объявление без распознанной даты — ошибка разбора, повтор.
- PDF-скан без текстового слоя (≤ 12 страниц, ≤ 8 МБ) модель читает как документ; пост помечается
  «скан, прочитан автоматически». Старый `.doc` и прочие нечитаемые файлы — сигнал владельцу, в канал не идут.
- Последние 3 новости AOD и 5 заявлений банка перечитываются: если по прежнему адресу появился новый абзац
  по теме — пост «дополнено» только с новым текстом.
- Пресса: впервые увиденное старше 3 часов — молча запоминается.
- Подборка прессы выходит при 3 материалах или когда старшему 30 минут; важное сверх лимита постов — в начале подборки.
- Бюджеты на прогон: 240 с, 10 вызовов модели (4 в резерве для официального), 8 сообщений, 3 отдельных поста прессы.

## Установка

1. Бот в @BotFather, канал, бот — админ канала. По желанию: ваш личный чат с ботом для сигналов и алертов
   (напишите боту /start и узнайте свой id через @userinfobot).
2. Репозиторий (публичный, чтобы минуты Actions не кончились) с этими файлами.
3. Секреты (Settings → Secrets → Actions): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
   `ANTHROPIC_API_KEY` (обязателен), по желанию `TELEGRAM_ADMIN_CHAT_ID`, `HEALTHCHECK_URL`
   (ping-адрес с healthchecks.io: алерт, если бот не отчитывается 30 минут).
4. Первый запуск: `BOOTSTRAP=1` в env workflow (или создайте `state/seen.json` из
   `{"seeded": false, "seen": {}}`) → Run workflow. Бот запомнит всё существующее и ничего не постит.
5. Внешний будильник: cron-job.org → POST `https://api.github.com/repos/<you>/alta-watch/actions/workflows/watch.yml/dispatches`,
   заголовки `Authorization: Bearer <fine-grained PAT, actions:write>`, `Accept: application/vnd.github+json`,
   тело `{"ref":"main"}`, каждые 2 минуты. Cron GitHub (5 мин) оставлен как запасной.
   PAT ограничьте одним репозиторием и сроком действия: через `force_urls` он косвенно даёт право публиковать.

## Состояние

`state/seen.json` — единственная память бота. Записи: `status` ∈ seeded / sent / pending / retry /
quarantine / dup / rejected / signal, плюс `message_id` у отправленных, `attempts` у повторов,
`title_src` (заголовок в оригинале — для дедупликации), `paras` (отпечатки абзацев перечитываемых страниц).
Разделы: `recent` (суть опубликованного за сутки для новизны), `pending` (накопитель подборок),
`retry_items` (метаданные отложенной прессы), `facts` (реестр фактов процедуры, без срока жизни, с историей),
`flags`, `signals`, `health` (здоровье источников, алерты, последний прогон).

- Все отправляющие запуски в одной очереди (`concurrency: alta-watch-publisher`).
- Состояние пишется атомарно и сразу после каждой доставки.
- Повреждённый файл = остановка без публикаций. Не перезаписывайте его при обновлении кода.
- При гонке push `merge_state.py` сливает все разделы; после 4 неудач job падает.
- `DRY_RUN=1` пишет в `state/dry_run_state.json`, боевой файл не трогает.

## Что приходит в админ-чат

- ⚡ Сигналы: непроверенное, Telegram-каналы, документы без текста, скан с неясным предметом,
  официальный материал, не обработанный после 5 попыток.
- 🚨 Алерты (не чаще раза в 6 часов на причину) и ✅ восстановление: API модели недоступен;
  AOD/NBS/сайт банка не читаются 3 прогона подряд; у объявлений AOD пропали даты (сломалась разметка).
- 📊 Ежедневный отчёт после 9:00 по Белграду: решения за сутки, очереди, карантин, здоровье источников,
  реестр фактов, активные алерты, версия.

## Ручные запуски

Actions → alta-watch → Run workflow: `force_urls` (опубликовать ссылки, включая PDF, минуя фильтры —
только с доверенных хостов: aod.rs, nbs.rs, altabanka.rs и ленты прессы из списка;
**на время прогона выключите будильник на cron-job.org**, иначе очередь может его вытеснить),
`backfill=1` (подборки за 48 ч).

## Проверка локально

```
pip install -r requirements.txt
python -m unittest discover -s tests -v          # без сети и ключей
DRY_RUN=1 ANTHROPIC_API_KEY=... python watch.py  # живой прогон без публикаций
```

Тесты запускаются и в Actions (`tests.yml`) при изменении кода.

## Остановить

Actions → alta-watch → Disable workflow, выключить задачу на cron-job.org. Токен бота — `/revoke` в @BotFather.
